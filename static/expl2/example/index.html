2. 章节标记 / Chapter markers

每章都要能进入全局目录 / Every chapter belongs in the global directory

给章节加 `data-expl2-chapter` 后，共享框架才能生成左侧目录并处理整页跳转。The shared framework needs chapter markers to build navigation and snapping.

Details / 详细

样例页展示最小规则：项目只标记章节，不自己实现目录。这样所有 expl2 页面会有一致的滚动、跳转和可访问标签。

The sample shows the rule: mark chapters, but do not implement a local table of contents. Shared behavior keeps pages consistent.

Marker

<section data-expl2-chapter>

3. 短文 / Short text

多页体验先给短句 / Multi-page reading starts with short prose

短文本推动阅读，不把整篇说明一次塞给读者。Short text keeps the chapter path light.

Details / 详细

超过三句话的解释应该放进 details，或者在单页版完整展开。这样主页面适合逐章阅读，单页版适合线性长读。

Long explanations belong behind details or in the single-page version. The main page stays navigable while the single page remains complete.

Text depth

short first, details on demand

4. 视觉支架 / Visual support

每章都需要一个可看的区域 / Every chapter needs something visible

即使是样例，也要给每章一个图、卡片或可操作区域。Even a sample chapter needs a visual or operable support.

Details / 详细

视觉支架不必复杂；它只要帮助读者抓住这一章的概念。真实项目可以换成图表、模拟、画布或控件。

The visual does not need to be complex; it only needs to support the chapter's concept. Real projects can use charts, simulations, canvases, or controls.

Visual

concept → support → observation

5. 关键概念 / Key concepts

定义交给共享弹窗 / Definitions use the shared popover

项目只提供概念数据，弹窗行为由 `_shared` 统一处理。Projects provide concept data; shared code owns the popover behavior.

Details / 详细

这让每个项目的关键概念有一致的键盘、鼠标和语言行为。项目不需要复制弹窗实现，也不需要重新解决可访问性细节。

This keeps keyboard, pointer, and language behavior consistent. Projects avoid duplicating popover code and accessibility details.

Concept API

data-expl2-concept + Expl2.applyConcepts()

6. 二级页面 / Secondary pages

概念树、目录和单页版补足主页面 / Secondary pages complete the main page

主页面负责交互路线，二级页面负责依赖关系、目录和完整线性阅读。The main page is the interactive path; secondary pages carry structure and full reading.

Details / 详细

概念树说明依赖，目录说明阅读顺序，单页版把所有文字摊开。样例页把这些入口放在顶部，提醒新项目不要只做一个孤立页面。

The concept tree explains dependencies, the directory explains reading order, and the single page unfolds all text. The sample keeps these entries visible.

Page set

main · tree · directory · single

7. 本地状态 / Local state

页面状态只保存本项目关心的东西 / Local state stays topic-specific

滑块值属于样例项目；语言、目录和概念弹窗属于共享框架。The slider is local; language, navigation, and concepts are shared.

Details / 详细

这个边界能让项目简单：主题逻辑留在项目目录，跨项目基础设施留在 `_shared`。新项目越早保持这个边界，后续维护越轻。

This boundary keeps projects small: topic logic lives in the project, cross-project infrastructure lives in `_shared`.

Ownership

project state vs shared behavior

8. 验证 / Validation

样例也要能被检查 / Samples should be checkable too

最小项目仍应通过脚本语法检查和 Hugo 构建。Even the smallest project should pass script checks and a Hugo build.

Details / 详细

样例页是后来项目复制的起点。如果样例不可靠，错误会被复制到更多页面。把验证写进习惯，比事后修每个项目更轻松。

The sample is copied by future projects. If it is unreliable, the mistakes spread. Verification habits are cheaper than repeated repairs.

Checks

node --check · hugo build · review doc
